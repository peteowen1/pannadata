# pannadata pipeline

_Generated by `ops/scripts/pipeline_guide.py` from `docs/pipeline.json`, using runs up to 25 Nov 2026, 4:03am (Sydney time). Do not edit by hand, except the notes section: rerun the generator._

How the football data gets from Opta to the site's R2 store, on GitHub Actions: the daily Opta scrape here, then the ratings and match predictions in the panna repo (see that repo's pipeline guide), then the blog data build here, which publishes what the site reads. Each stage starts the next by sending a repository_dispatch message; this guide times each stage on its own and does not follow one chain of runs across repos.

## Daily Opta scrape

Workflow: [`daily-opta-scrape.yml`](https://github.com/peteowen1/pannadata/blob/HEAD/.github/workflows/daily-opta-scrape.yml). Median wall time **29 min 13 s** (range 26 min 27 s to 1 h 01 min), from the first job starting to the last job ending, over the 5 run(s) listed below.

Fetches new Opta matches for the current season, merges them into the consolidated tables, scores new shots for xG and post-shot xG (xGOT), and publishes everything to the opta-latest release. Only the scheduled runs are counted, not manual backfills. Tuesday to Sunday it scrapes competition tiers 1 and 2; Monday it scrapes every tier (the scrape limit rises from 35 to 120 minutes), so Monday runs are the slow ones.

**What starts it, and what it starts:** GitHub's own schedule, set for 4pm Sydney time each day in summer. GitHub starts it hours late (the five runs used began between midnight and 3am Sydney time). When it succeeds it sends opta-scrape-complete to the panna repo, which starts both the Predictions Pipeline and the Opta RAPM/SPM Pipeline there.

## Blog data build

Workflow: [`build-blog-data.yml`](https://github.com/peteowen1/pannadata/blob/HEAD/.github/workflows/build-blog-data.yml). Median wall time **27 min 34 s** (range 24 min 20 s to 28 min 43 s), from the first job starting to the last job ending, over the 5 run(s) listed below.

Takes the ratings and predictions the panna repo published, joins them to the Opta data, builds the parquet files the site reads, and uploads them to the R2 store (inthegame-data, football folder). Only runs started by the panna repo's predictions-complete message are counted.

**What starts it, and what it starts:** The panna repo's Predictions Pipeline sends predictions-complete when it finishes publishing (a step near the end there). It can also be started by hand. It starts nothing else: the site reads the R2 files it uploads. It shares a queue with the daily scrape, so the two never write R2 at the same time.

## How to regenerate

```
python C:/dev/ops/scripts/pipeline_guide.py build --repo-dir <this repo>
```

It reads `docs/pipeline.json` (which workflows and jobs are the pipeline, one line per step) and the latest successful runs through `gh`, saves every response raw, and rewrites this file and `docs/pipeline-summary.json`. It fails if the config names a job, step or log pattern that no longer appears, so a renamed step cannot leave a stale description behind. Steps marked **(not confirmed)** were not checked against the script they run.
